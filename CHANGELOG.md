# Changelog — verse-profiteer  

Format: one entry per shipped version. Newest on top. CC never edits this in a code prompt — doc updates are a separate prompt after code is committed.

## [2026-06-10]

- Spine read view shipped (the companion's first numbers): lib/planView.ts bundles the spineDerive functions into one PlanDerivedView and NEVER throws — on corrupt data it returns { view: null, error } so the raw rows still serve (a bad entry can be seen and fixed, not 500 the page). GET /api/plans/[id] now derives server-side (where occurredAt is a real Date) and returns { plan, legs, items, derived, derivedError }. app/PlanComposer.tsx renders a Status panel (current position, realized profit in profit/loss colors, unrealized-at-cost, in-hold carry) and per-leg profit with [LOCKED] / dimmed-flown badges; a warning banner replaces the numbers when derivedError is set. First spine surface showing money — realized accounting of entered data, not a forward-looking claim. See VERIFICATIONS.
- Board card legibility: route cards now carry aUEC units — buy/sell prices as "aUEC/SCU", the per-SCU margin labeled "P/L … aUEC/SCU", and the headline + expanded realizable figures suffixed "aUEC". Display-only; no ranking or math change.

## [2026-06-09]

- Cargo-ledger spine schema shipped (migration 0001): four tables in lib/db/schema.ts — plans, legs, items, price_observations — implementing the Plan/Leg/Item model and D9's trip-being-flown frame. legs has no status column (the ledger is the lock); items is the actuals ledger (acquire/dispose), not a planned manifest; price_observations holds manual ground-truth sightings that supersede UEX when newer. All status/activity fields are plain text (not pgEnum) to keep adding money-loops migration-free. tenant_id defaulted 'operator'. No reads/writes yet — schema + tables only. See DECISIONS D10.
- Worker auto-migrate: scripts/refresh-mirror.ts now runs migrate() through its pool on startup (after the probe, before table access), applying any pending ./drizzle migrations automatically and idempotently. Amends D4's manual-migrate workflow; sidesteps the missing-SSL gap in drizzle.config.ts. Verified — the four spine tables are present after a real worker run. See DECISIONS D11 and VERIFICATIONS.
- Spine accessor shipped: lib/spineRepo.ts — thin async CRUD over plans/legs/items/price_observations, modeled on routesRepo.ts. Re-exports Drizzle inferred types (Plan/Leg/Item/PriceObservation + New* insert types) as the single source of truth. Reads/returns rows verbatim — no derived math (carry-state/profit/etc. are a later read-time beat), no deletes (plan->legs/items cascade handles teardown). numeric columns return as string and are not coerced here.
- Derive-on-read layer shipped: lib/spineDerive.ts — pure functions (no DB, no UEX) over spine rows: carryState, avgUnitCost (plan-wide weighted average, acquire fees capitalized), planRealizedProfit and legProfit (COGS-based and reconciling — leg sum = plan total), unrealizedInventoryValue, currentPositionTerminalId, executedLegIds, lockedLegIds. Corrupt data (non-numeric price, dispose with no acquisition, negative carry) throws rather than fabricating a number. Unit-tested with hand-computed expecteds (28 cases, all green). Estimate-vs-actual, ranking-price supersession, and aUEC/hr remain deferred (need the mirror / travel-time). See VERIFICATIONS.
- Spine write path shipped: lib/spineValidate.ts (pure input validation/normalization — throws SpineValidationError mapped to HTTP 400; numeric prices normalized to string; disposition-on-acquire and non-finite prices rejected; unit-tested) plus four App Router routes — POST/GET /api/plans, GET /api/plans/[id] (aggregate plan + legs + items), POST /api/plans/[id]/legs (server-assigned seq), POST /api/plans/[id]/items (cross-plan legId guard). Handlers stay thin: validate -> assign server-owned fields (tenantId/status/seq/occurredAt) -> spineRepo -> raw row. No derived math, no observation endpoint yet. These write endpoints are UNGATED (sole-user) and must be gated before public traffic (see TODO).
- Manual composer UI shipped: /plan (app/plan/page.tsx server shell + app/PlanComposer.tsx client) — create a plan, add legs, log acquire/dispose items, reusing SearchableSheet for terminal/commodity pickers. Renders RAW stored rows (ids resolved to names for legibility) and deliberately shows NO derived numbers (carry/profit/position/locks) — that is the read-view beat. First user-facing surface of the spine; ungated like the write routes.

## [2026-06-08]

- /api/verify migrated to read the Postgres mirror (getMirroredRoutesByCommodity in lib/routesRepo.ts) instead of live UEX (getCommodityRoutes). The raw debug button now verifies against the same source the board ranks from, so spot-checks no longer show spurious mismatches. Test updated to mock the repo accessor; CI green.
- Removed dead code: shortlistCommodities and SHORTLIST_SIZE in lib/routes.ts (unused since the D3 read-path migration dropped the top-35 shortlist) and their unit tests. Clears the lint warning.
- Staleness-display honesty fix: card label changed from "Updated {N} ago" (which read date_added — route-row creation time, not a freshness signal) to "prices last seen {N}", computed as the older of the two price legs' date_modified, joined in-memory in getTopRoutes (dataAgeUnix on RouteWithAutoLoad, derived-on-read). Reads "price age unknown" when either leg is absent from the prices feed. Rationale: date_modified is last-human-observation, not last-price-change, so the label is an observation timestamp, not a freshness promise. State-sensitive — see VERIFICATIONS Pending.
- Loop plan-view spike (app/spike/loop) — throwaway hand-authored 3-stop Stanton loop to probe the multi-leg UX before building the cargo-ledger spine. Surfaced the loop planner's objective function and leg model; captured as DECISIONS D7. Spike is fake-data and slated for deletion (see TODO Chore).
- Location-origin routing: getTopRoutes gained an optional originTerminal filter (matches id_terminal_origin); board can now show only routes departing a chosen terminal. URL param &origin=<terminalId>, read in page.tsx. Ranking-input change — see VERIFICATIONS Pending.
- Origin picker only lists real route origins: new getDistinctOriginTerminalIds() in lib/routesRepo.ts; page.tsx intersects the terminal list with that set so non-trading kiosks (e.g. food/refuel terminals) no longer appear as selectable origins.
- New reusable SearchableSheet component (app/SearchableSheet.tsx): a searchable + scrollable bottom-sheet picker (browse the full list, or type to narrow), recognition-rich rows (primary name + system/location subline), optional trailing value + proportional bar. Tall sheet (90svh), grab handle, hairline row dividers. Mobile keyboard handling: list bottom-padding so all rows clear the on-screen keyboard, Enter blurs the input to dismiss the keyboard, enterKeyHint=done.
- OriginPicker and ShipPicker both refactored to use SearchableSheet. ShipPicker keeps capacity browsing (SCU value + bar per row, biggest-first) plus name search, replacing the old card grid. All pickers preserve the full query string (systems/ship/autoLoad/origin) on navigation.
- Always-dark theme fix: base --background/--foreground were light-mode scaffold defaults that only flipped dark under prefers-color-scheme. The app's card tokens are hardcoded dark, so in OS light mode text rendered dark-on-dark (the whole app was broken in light mode). Pinned the base theme to its dark values and removed the OS-scheme dependency.

## [Unreleased]

### Added

- Buy & sell prices on each route row. `price_origin` (buy at origin) and `price_destination` (sell at destination) — already returned by `commodities_routes` but previously untyped/unrendered — added to the `CommodityRoute` interface in `lib/uex.ts` and shown per row as "buy {price_origin}/SCU · sell {price_destination}/SCU" (toLocaleString formatting, existing tokens). Display-only; no new fetch, no ranking change. Verified on production: card math reconciles (sell − buy = per-SCU; per-SCU × supply = headline profit; per-SCU × capacity = realizable). Note for future work: the `commodities_routes` response is richer than the `CommodityRoute` interface (see TODO key finding) — type missing fields from the raw response rather than assuming the interface is complete.
- Profit-per-hour per route. lib/profitPerHour.ts: profitPerHour(route, shipCapacity) = realizableProfit / (estimateTravelMinutes / 60), divide-by-zero guarded, shown as +{value}/hr per row. Derives from travel-time constants so it recomputes on calibration. Display-only; ranking still on total profit. Unit tests in lib/profitPerHour.test.ts.
- Cards collapsed to one primary route by default, with a "+N more routes" inline toggle (per-card expand state) to reveal the rest. Reduces row density on mobile.
- Temporary debug surface /api/verify-qt + DebugQt ("{ } qt" button) to inspect UEX categories and items_attributes, with copy + download-JSON. UNGATED — strip/gate before public traffic.
- Ship-capacity scaling. New lib/realizableProfit.ts: realizableProfit(route, shipCapacity) = profitPerScu × min(shipCapacity, scu_origin, scu_destination), and routeBottleneck(route) = min(scu_origin, scu_destination). Capacity falls back to the route bottleneck when unset/invalid. A global ship-capacity input (in-memory, no persistence) was added; the interactive board moved into a client component (app/Board.tsx) while data fetch/ranking stays in the server component. Each route row shows realizable profit and a "caps at N SCU" indicator when capacity exceeds the route bottleneck. Safety invariant (unit-tested): realizable profit can never exceed the route's total profit — it scales down for undersized ships, never up. Display-only; ranking still on total profit. Unit tests in lib/realizableProfit.test.ts.
- Travel-time estimate per route. New lib/travelTime.ts: estimateTravelMinutes (point estimate = spool + distance/QT-speed + terminal overhead + load/unload×scu_origin) and estimateTravelRange (point ± a flat band). Four calibration constants (QT_SPEED_GM_PER_MIN, SPOOL_CALIBRATE_MIN, TERMINAL_OVERHEAD_MIN, LOAD_UNLOAD_MIN_PER_SCU) plus ESTIMATE_BAND_PCT, all seeded as uncalibrated guesses. Inputs (distance, scu_origin) come free from commodities_routes — no new UEX calls. Each route row shows an estimated time range with an uncalibrated-seed caption. Display-only; ranking unchanged. Unit tests in lib/travelTime.test.ts.
- Profit-per-SCU per route. New lib/profitPerScu.ts: profitPerScu = profit / scu_origin (divide-by-zero guarded, rounded to whole credits). Basis verified against asymmetric-SCU routes — profit is bottlenecked to scu_origin in observed UEX data. Displayed compact as {value}/SCU on every route row. Display-only; ranking unchanged. Unit tests in lib/profitPerScu.test.ts.
- v0.1 route planner. Pure `planRoutes` module (`lib/routePlanner.ts`) pairing lowest valid `price_buy` vs highest valid `price_sell` per commodity into single-leg routes, ranked by profit per unit, default top 50. Typed `CommodityPriceRecord` interface in `lib/uex.ts` replacing the untyped passthrough. `/api/routes` GET handler. Mobile-first card UI on the home page showing commodity, profit/unit, buy to sell with prices, and `date_modified` age with a stale (>30d) warning. Unit tests for the planner (8 cases, vitest). Verified against UEX: Aluminum profit/SCU 1,416 (buy Rod's Fuel 2,584, sell Dudley & Daughters 4,000) matched the live UEX commodity page.
- Server-side UEX proxy: `lib/uex.ts` data-access module (the single place that calls UEX) and `app/api/commodities/route.ts` GET handler returning the `commodities_prices_all` data array. Token and base URL read from env (server-side only); 5-minute fetch cache; env-presence and response-shape guards. Verified against live UEX (2,581 records, spot-check matched site).
- GitHub Actions CI (lint + typecheck + test) running on pull requests into main and on push. Adopted a PR-into-main step; CI status on the PR gates merges by convention (no enforced branch protection).
- Route-count guard: commodities with a single profitable route (per the full UEX response) are quarantined below all corroborated commodities and labelled 'single route — unverified', rather than ranking on an uncorroborated profit figure. Threshold starts at <=1 route.
- Added copy-to-clipboard buttons to both debug panels (DebugRoutes per-card '{ } raw', and DebugPrices '{ } prices').
- Added a temporary ungated '{ } prices' debug button + /api/verify-prices endpoint exposing the raw commodities_prices_all feed (the cheap bulk call the shortlist is built from), for auditing candidate selection against source.
- Added download-as-JSON to both debug panels (DebugRoutes, DebugPrices) alongside copy.

### Changed

- Realizable-profit values are now sign-aware in the route board. The card headline and the per-route realizable line use the loss token (text-loss) when the value is negative and the profit token (text-profit) when it is zero or positive, and no longer prepend a hardcoded "+" (toLocaleString already emits the minus sign). Fixes negative routes rendering as "+-90,500" in profit-green; a loss now reads as a red negative. Display-only, no ranking or math change. Verified on production.
- Replaced the local route planner with UEX commodities_routes integration. New `lib/routes.ts` (`shortlistCommodities` + `getTopRoutes`) selects top-margin commodity candidates from the cached prices feed, fetches real UEX routes for those candidates, and ranks by realizable profit.
- Routes board now renders one card per commodity (top 3 routes each, origin → destination + profit), sorted by best-route profit, showing the top 10 commodities.
- Card information hierarchy redesign (display-only, verified in production). Card headline now shows the primary route's realizable profit (capacity-aware), not total. Per-route green realizable profit shows only when a card is expanded (fixed prior double-count on collapsed cards). Per-row qualifier shows "pick up {haulable} SCU · {supply} available" when capacity is set, "at {bottleneck} SCU max supply" when unset. Total profit demoted behind expand; per-SCU on secondary line.

### Removed

- Retired `planRoutes`, the `Route` interface, `lib/routePlanner.ts`, `lib/routePlanner.test.ts`, and the `/api/routes-spike` endpoint.
- Profit-per-hour removed from the card. Rationale: single-run per-hour overstates sustained earnings (ignores supply refill, empty return leg, and per-shard demand depletion). Per-hour belongs in the future multi-leg loop planner. lib/profitPerHour.ts retained on disk, not deleted.

### Fixed

- Fixed commodity name visibility on cards and removed the unexplained distance line pending travel-time work.
